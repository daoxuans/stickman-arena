# 线斗 · 火柴人竞技场

一款本地运行的网页版火柴人格斗游戏：56 关单人闯关，以及通过同一台游戏服务连接的实时 1v1 对战。无需账号或云端服务；场景照片随游戏一起存放在本地，音效由程序合成。

## 启动

需要 Node.js 20 或更新版本。在 PowerShell 中进入本目录，然后运行：

```powershell
npm install
npm start
```

浏览器打开 <http://127.0.0.1:3000/>。开发时可以运行 `npm run dev` 自动重启服务；自动化测试运行 `npm test`。如果你的受限终端阻止 Node 测试启动子进程，可用 `node --test --test-isolation=none`。

### 两台设备在同一局域网对战

在作为房主服务的电脑上运行：

```powershell
$env:HOST = '0.0.0.0'
npm start
```

两台设备都访问 `http://<服务电脑的局域网 IP>:3000/`。一方点“联机对战 → 创建对战房间”，把六位房间码给另一方；另一方输入房间码加入。若连接不上，检查两台设备能否访问同一局域网地址，以及服务电脑的防火墙是否放行 TCP 3000。端口冲突时先设 `$env:PORT = '3001'`，两台设备改用该端口。

服务默认只监听 `127.0.0.1`，不会自动公开到互联网。当前房间码没有账号认证，服务本身也没有 TLS；不要把裸 HTTP/WS 服务直接暴露到公网。公网对战需要另行部署到可访问的服务器，并配置 HTTPS/WSS 反向代理及访问防护。

## 操作与打击反馈

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动 | A / D 或左右方向键 | 左 / 右按钮 |
| 攻击 | J | 攻击按钮 |
| 踢腿 | K | 踢腿按钮 |
| 跳跃 | 空格 | 跳跃按钮 |
| 空中跳踢 | 跳起后在空中按 K | 跳起后在空中按踢腿按钮 |
| 闪避 | Shift | 闪避按钮 |

连续按攻击键可接三段招式；踢腿和空中跳踢也属于近身招式，每次出招对同一目标只结算一次。火柴人采用夸张的大头、细身和细肢比例，让跳跃、踢腿与受击姿态更醒目。跳踢在有效攻击帧释放脚端能量、定向碎光、扩散环和短促震动；未命中也有完整动作，低动态设置会减弱尾迹与粒子。跳跃带有短暂的离地宽容和提前输入缓冲；闪避有约 0.18 秒无敌时间及约 0.9 秒冷却。战斗按固定 60 帧模拟重力、摩擦、单向平台、碰撞、击退和受击硬直。命中还会触发短暂停顿、粒子、合成音效与轻微镜头震动。角色被击倒时，烂番茄会从上方砸向头部并破裂，湿润的合成砸开声与落点同步；结果面板会短暂延后，让玩家看清这一幕，低动态模式缩短等待。音效开关同时控制番茄声；“真实感”来自这些可读的反馈，**不是三维刚体或布娃娃物理**。

## 56 关与存档

| 关卡 | 场景 | 存档关 | 首领关 | 场景机制 |
|---|---|---|---|---|
| 01–14 | 森林 | 01、05、09、13 | 14 | 树冠、倒木平台、荆棘 |
| 15–28 | 城市 | 15、19、23、27 | 28 | 天际楼群、屋顶平台、交通危险区 |
| 29–42 | 海洋 | 29、33、37、41 | 42 | 海面、码头/甲板平台、潮汐危险区 |
| 43–56 | 陆地 | 43、47、51、55 | 56 | 荒原山峦、岩台、地裂危险区 |

每关有自己的名称、敌人波次、敌人类型与强度、平台和机关配置。进入存档关时自动激活存档；失败立即把进度写回最近的存档关，点“重试”后从该关的满血起点重建敌人和机关。例如第 11 关失败回第 09 关，第 14 关失败回第 13 关。刷新网页会从已记录的当前关卡起点重新开始，不能跳过失败后必须重打的关卡。

闯关记录存于当前浏览器的 `localStorage`，不在多设备间同步。清除浏览器网站数据会清除存档；当浏览器禁止本地存储时，本次打开期间仍可游玩，但刷新后无法保留进度。联机胜负不影响闯关存档。

### 照片背景

森林、城市、海洋、陆地四个主题各有 4 张由原照片裁剪、压缩而成的背景。每章仍固定选出 4 关使用照片，这 4 关各用一张不同的图；整条 56 关路线的照片关卡彼此不相邻。照片与关卡的对应关系固定，刷新、失败回档和重试后不会随机换图。其余 40 关继续使用原本的绘制场景，关卡的平台、机关和碰撞规则不会因背景照片改变。

照片仅在被选中的单人关卡按需加载，并轻柔渐入；若图片尚未加载或加载失败，画面自动保留对应主题的绘制背景。联机对战始终使用绘制场景，双方的对战画面和碰撞规则不受照片加载影响。公开目录 `public/assets/backgrounds/` 仅有 16 张已去除拍摄信息的 1600×900 WebP；原始照片只保留在本机被 Git 忽略的 `pic/` 中，不随仓库上传，克隆后也无需原图即可运行。新加入照片的来源与授权页见 [`BACKGROUND_DOWNLOADS.md`](BACKGROUND_DOWNLOADS.md)。

## 联机规则

两名玩家加入同一房间后倒数三秒开赛，单局 99 秒。服务端以固定 60Hz 计算位置、碰撞、命中、血量和胜负；客户端发送带递增序号的按键状态，接收约 20Hz 的战斗快照，并对画面做有限平滑。击倒或倒计时结束时结算；双方都申请后才开始重赛。对手断线时，房主的房间回到等待状态，可让新玩家加入；房主断线则房间关闭。

## 项目结构与验证

- `shared/combat.js`：闯关与联机共用的确定性战斗模拟。
- `shared/levels.js`：四主题、56 关和存档点的数据配置。
- `public/campaign.js`：单人波次、通关与失败回档。
- `public/app.js`、`render.js`、`styles.css`、`index.html`：输入、房间交互、画面、音效与响应式界面。
- `public/assets/backgrounds/`：四主题各 4 张可选闯关照片背景；本机 `pic/` 中的原图既不会被游戏服务公开，也不会进入 Git 仓库。
- `server/index.js`：静态资源和 WebSocket 房间服务。
- `test/`：关卡/存档、物理、网络房间、照片选图与资源接线测试。

本地自动化测试覆盖所有 56 关的配置与短时实战模拟、存档回退/刷新、攻击去重/闪避/平台/机关，以及两客户端 WebSocket 房间、同步、异常输入、超时、重赛和断线。它不代替跨设备的手感与网络压力测试。
