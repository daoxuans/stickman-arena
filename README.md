# 线斗 · 火柴人竞技场

一款本地运行的网页版火柴人格斗游戏：56 关单人闯关，以及通过同一台游戏服务连接的实时 1v1 对战。单人关卡在 1920×540 的横向场地中推进；联机战场为 2880×540，是原来 960 宽的三倍。两种模式都用 960×540 视口跟随本方角色。无需账号或云端服务；场景照片随游戏一起存放在本地，背景音乐与战斗音效由程序合成。

详细的现行版关卡结构、操作机制、联机房间、失败重试、场景与验收口径见 [功能与内容 PRD](outputs/PRD-火柴人竞技场-20261004.md)。

协作者和 AI 助手请先看 [AI 协作约定](AGENTS.md) 与 [协作开发指南](CONTRIBUTING.md)；修改代码时参考 [架构与状态边界](docs/ARCHITECTURE.md)、[视觉与交互设计基线](docs/DESIGN_BASELINE.md) 和 [决策记录](docs/DECISIONS.md)，将新决定留在仓库而不只留在聊天记录中。

## 启动

需要 Node.js 20 或更新版本。在 PowerShell 中进入本目录，然后运行：

```powershell
npm install
npm start
```

浏览器打开 <http://127.0.0.1:3001/>。开发时可以运行 `npm run dev` 自动重启服务；自动化测试运行 `npm test`。如果你的受限终端阻止 Node 测试启动子进程，可用 `node --test --test-isolation=none`。

### 两台设备在同一局域网对战

在作为房主服务的电脑上运行：

```powershell
$env:HOST = '0.0.0.0'
npm start
```

两台设备都访问 `http://<服务电脑的局域网 IP>:3001/`。一方点“联机对战 → 创建对战房间”，把六位房间码给另一方；另一方输入房间码加入。若连接不上，检查两台设备能否访问同一局域网地址，以及服务电脑的防火墙是否放行 TCP 3001。端口冲突时可先设 `$env:PORT = '3002'`，两台设备改用该端口；同一时间只需启动一个游戏服务。

服务默认只监听 `127.0.0.1`，不会自动公开到互联网。当前房间码没有账号认证，服务本身也没有 TLS；不要把裸 HTTP/WS 服务直接暴露到公网。公网对战需要另行部署到可访问的服务器，并配置 HTTPS/WSS 反向代理及访问防护。

可操控的火柴人采用深色侠客造型：宽檐、破边且有编织纹理的蓑帽，默认脸有可辨情绪的亮眼，颈部围巾和随走动、跳跃、停步改变形态的披风。P1 披风偏赤红，联机 P2 使用清晰不同的冷色；普通敌人和 Boss 保持原造型。这是对用户所给侠客图片的游戏内简化演绎，不直接收录原图，也没有新增持刀攻击。服饰只影响画面，不改变命中或碰撞。

开战前点准备画面的“设置头像”或页头“我的头像”，可以在本机上传照片、用网页相机拍照；相机不可用/权限拒绝时可改用设备的系统相机或相册。单人战斗中打开设置会先暂停，关闭后按正式/练习显示“继续主线/继续重打”；联机倒数与正式对战期间不能修改。支持 JPG、PNG、WebP 和浏览器能解码的 HEIC/HEIF，文件最多 8 MB、边长不超过 8192 像素，头像缩为 192×192 后裁入“我方”大头；未选择或处理失败时保留默认脸/上一张有效头像，点“恢复默认头像”可清除。设置照片后，我方脸上不再叠绘游戏默认的眉、眼、嘴及胜负/连段表情；清除或刷新后恢复默认表情。帽子、头部轮廓、围巾、披风、KO 番茄、血量与结果文字仍正常显示。

图片只在当前网页内存处理，不上传到游戏服务、不进入闯关存档或联机消息；联机时每个人仅在自己的设备上看到自己的照片，不会把本机照片贴到对手头上。刷新后需要重新选择。网页相机是否可用取决于浏览器、设备、安全访问地址及其权限；在共享或公开含人像照片前，请自行确认肖像与使用授权。

连续按攻击键可接三段挥拳，拳头周围出现弧形拳风，不再射出箭头；踢腿和空中跳踢也属于近身招式，每次出招对同一目标只结算一次。火柴人采用夸张的大头、细身和细肢比例；未设置照片时胜利露出开心表情、被击败时伤心、连续挥拳中努力发力；我方设置有效照片后不叠这些游戏表情。Boss 身形更高大、肩部更宽，出拳前有明显预警。敌人会判断你所在方向，绕到其背后时会先转身再出招；玩家位于正上方时会继续追踪并寻找可命中的位置，不在高度分离时机械空挥。中后期敌人也可能投矛，但会先有可辨前摇。跳踢在有效攻击帧释放脚端能量、定向碎光、扩散环和短促震动；未命中也有完整动作，低动态设置会减弱尾迹与粒子。跳跃带有短暂的离地宽容和提前输入缓冲；闪避有约 0.18 秒无敌时间及约 0.9 秒冷却。战斗按固定 60 帧模拟重力、摩擦、单向平台、碰撞、击退和受击硬直。命中还会触发短暂停顿、粒子、合成音效与轻微镜头震动。角色被击倒时，烂番茄从上方加速砸向头部，先压扁再破裂，汁液向两侧飞溅并短暂留在头顶；湿润的合成砸开声与落点同步。单人敌人还会倒地，约 0.45 秒落稳后留在地上约 3 秒；玩家先离开，再站在尸体同一实际地面或同一块平台（包括移动、倾斜木条）上走过，尸体才会散成骨头并提前消失。隔着一块浅木板、仅看起来脚底接近不会触发。踩骨只提供反馈，不伤人也不额外积攒光波。若这是本关最后一名敌人，KO 后会有约 3 秒可左右移动和跳跃、免伤的收尾时间供玩家走过去；进入收尾时先前短按缓存的拳/踢/闪不会突然执行，普通攻击、踢腿、闪避、投矛与光波此时不可用。临近结束踩到骨头时会短暂等动效显示完再出现过关结果；自己被 KO 或双方同时 KO 仍按失败处理。暂停和打击停顿不计入这些有效战斗帧。低动态模式减少番茄飞溅与散骨运动，但保留砸中、污渍、骨头散开的关键线索和胜负反馈。联机仍有 KO 番茄，但没有踩骨。音效开关同时控制番茄声和散骨声；“真实感”来自这些可读的反馈，**不是三维刚体或布娃娃物理**。

“灵能武侠”声画升级让真正命中时出现短促白金墨锋与随森林、城市、海洋、陆地微调的碎光；跳踢以脚端玉色弧光为重点，光波从侠客身前聚能并朝面向方向打出玉白主光束，伴随较弱的环形余波和目标命中亮点，Boss 拳部聚起金色蓄势，避免整屏连续闪白。拳脚命中有破风与着肉的分层合成声，跳踢、光波和投矛各有音色；空挥拳不播放命中声。混音限制同时发声数量，静音或切换场景会清除待播尾音。减少动态效果时保留短促的定向光束、静态命中轮廓和 Boss 预警，但不震屏或播放长尾迹；这些效果不改变攻击范围、伤害和联机胜负。

背景音乐在森林、城市、海洋、陆地各有一段低音量合成循环，不需要额外下载音乐文件。单人只在战斗与末敌收尾时播放；联机只在正式对战时播放，使用房主选定的主题，等待、倒数和结算期间不循环。首次播放须先有浏览器允许的点击/按键等用户手势；页头“声音”开关同时控制音乐和打击音效。命中或 KO 时音乐短暂让位，拳脚着肉、光波和番茄等反馈保持更突出；关闭声音、页面失焦/隐藏或离开战斗时停止音乐，恢复焦点后仅在仍处于可播放的战斗阶段时继续。音量在不同扬声器、耳机和手机上仍需实际试听，不能仅凭自动化测试宣称混音已验收。

单人敌人追击玩家时会主动识别前方地面陷阱并尝试跳过或避开；即使被击退到陷阱附近，恢复追击后也不应机械地反复冲入同一区域受伤。这是敌人的路线选择，不是对陷阱伤害的免疫：实际碰上仍按原有规则扣血，玩家所受伤害和联机 PvP 规则不变。预判、起跳、安全落点及周期机关暂时等待的细节是本版实现选择，并非额外按键。

投矛与拳风是不同招式：拳风始终贴近拳头。可出招时第一次按 I（触屏点“投矛”）进入瞄准，角色面向的前方目标只用于估算初始角度；没有合适目标时默认为 42°，**不会自动锁定或追踪目标**。舞台出现随人物位置、朝向和角度更新的抛物线与预计落点；按 W 抬高、↓ 或 S 压低仰角（8°–72°），↑ 始终用于跳跃而非抬角；瞄准期间仍可用左右方向键或 A/D 走位、转身。再次按 I（触屏点“发射”）确认角度与朝向，随后蓄势约 20 个有效战斗帧再投出。投矛以固定速度沿确认的方向受重力飞行；由于玩家的惯性、移动平台、对手走位及遮挡，显示的预计落点只是**当前起点的理论参考**，并不保证命中。触屏还可在舞台上竖向拖动调角，松手不会自动发射，需点“发射”。

Esc 或触屏“取消”退出未确认的瞄准；在瞄准中按攻击、踢腿、跳跃或闪避会取消瞄准并照常尝试该动作，受击/KO 或页面失焦也会退出瞄准。单人暂停或切模式同样取消未确认的瞄准；联机切模式则离开房间。闯关满足光波资格且有充能/活敌人，或联机已充能且仍在战斗时，按 L/触屏“光波”可打断瞄准或蓄势并释放；无充能时不会取消瞄准。已确认的蓄势不因 Esc 或失焦倒退；单人暂停/切模式时保留蓄势，返回闯关后继续有效帧，联机失焦后服务端仍继续推进本局、切模式离房后不保留该局。受击或成功释放光波会打断本次发射；蓄势中不能主动移动或叠加拳脚/跳/闪。投矛**闯关每关最多 5 发，联机每局每人最多 5 发**：进入瞄准、确认蓄势、取消或蓄势被打断均不扣，真正投出时才扣 1 发；闯关各波共享本关余量，联机重赛重置，余量为零不能再瞄准。按住 I 不会连发。第 15 关起部分单人敌人仍按原节奏预警后投矛；联机双方自行调角，实弹轨迹、平台遮挡和命中由服务端判定。

单关预设敌人总数超过 3 名时，击倒每 2 名敌人可积攒 1 次闯关光波；按 L 或触屏按钮释放，对当前波次所有存活普通敌人造成「剩余血量减半」、对 Boss 造成「剩余血量减去三分之一」（即剩余 `ceil(原 HP × 2/3)`），并让玩家约 0.6 秒无敌。闯关主光束面向前方，但余波让**当前波所有存活敌人**（含身后）受影响；Boss 召唤的小兵不计开关资格，玩家亲自击倒它们仍可累计充能。联机光波是独立的公平对战规则：每人每局通过三次本人非光波的真实伤害命中（拳、踢或矛）充一次，上限储存一次；L 向当前面向方向释放约 800 距离、胸部中心上下约 42 的光束，命中造成固定 20 点伤害，释放者约 18 有效帧受保护。对手可用闪避/无敌抵挡，躲出束的范围也不会受伤；机关、光波自身伤害不累计充能。联机伤害与画面事件都由服务端生成，不套闯关的全波比例伤害。

### 首领战利品与装备背包

单人闯关的九场 Boss（10、14、20、28、30、40、42、50、56）各固定掉落 **1 件**不同的装备，不靠随机概率；Boss 真正 KO、玩家仍存活时，战利品出现在 Boss 倒地位置，经过移动平台会随尸体移动，随后落向可接近的地面。此时仅该 Boss 召唤的存活小兵同步 KO，预设敌人或其他来源的小兵不受连带影响；连带 KO 不算玩家亲自击倒，不额外充光波。若仍有不受影响的活敌人，须继续清空才能过波，但掉落无需等待。约 14 个有效战斗帧后走近会自动拾取；最后一敌 KO 后仍可在可移动的收尾阶段去捡，没走到的掉落在正式过关时也会自动收纳，不会因为场地很宽或收尾时间短而错过。同一件装备不重复叠加。刚取得的装备可在本关使用，但只有**正式过关**才记入本浏览器的背包；玩家被 KO（包括双 KO）仍按原规则失败，回最近存档关时连同装备一起回滚至该存档关的快照。

按 B 或点“背包”打开装备列表，战斗暂时停住；列表显示阶级、伤害、射程和出招间隔，选择一件后按 E 或触屏“装备技”发动。首次拾得会自动装备；后续掉落只加入背包，不强制替换当前选择。装备技是有起手、近身/中距判定和冷却的**单目标**独立招式，不是远程投射物、全屏群伤或可按住连发；与拳、踢、闪、投矛蓄势及未确认瞄准互斥，胜利收尾时不可使用。当前九件按关卡渐进：基础伤害 15–24、射程 88–126 逻辑像素、冷却 44–60 个有效战斗帧（约 0.73–1 秒），命中仍受朝向、高度、闪避/无敌与 Boss 护体影响。拳连段为 9/11/17、跳踢 16、投矛 22 基础伤害，因此装备有提高出手效率的层次，但不替代走位、拳脚和光波；具体平衡数值是本版选择，可按实测调整。

里程碑 Boss 每次召唤至多 2 名小兵，但同场存活的召唤兵总上限仍为 5 名；不能把“单次”上限当成“场上”上限。

每关有自己的名称、敌人波次、敌人类型与强度、平台和机关配置。第 8 关起出现机动跳袭的「跃袭者」，第 18 关起出现抛小石的远程「石掷手」；它们替换预设波次中的部分常规兵位，不凭空增加每关预设人数。石掷手使用自己的小石，不叠加旧敌人的投矛。每章从三阶楼梯起步，第 4 关位起增加楼梯高度，第 5 关位起有上下浮动台阶，第 6 关位起增加另一组楼梯，第 8 关位起出现旋转木条，第 11 关位起第二个浮台改为左右漂移（章内 11–14 关位分别为 ±20/24/28/32 逻辑像素），第 13 关位再加入木条；浮台移动、碰撞与人物承载同步，首关没有动态平台或地面机关。第 10、20、30、40、50 关在原有敌人波次之后追加一名 Boss，原来的章节 Boss（14、28、42、56 关）继续保留；进入 Boss 波前会恢复部分生命值。五位里程碑 Boss 随关数逐级累加投石、召唤小兵、震地、双石连投和短暂护体；召唤仅在 Boss 存活时发生，同场最多 5 名活召唤兵。章节 Boss 保持既有拳法定位。每个偶数关约每 4 秒预警并坠落一件主题小物体，一次只落一件；命中玩家或敌人会扣除其最大生命值约 10%，可通过走位或闪避躲开，奇数关与联机对战没有坠物。落点在预警时根据场上人物位置确定，之后不再追踪；相同操作下重试时序可复现。

进入存档关时自动激活存档；失败立即把进度写回最近的存档关，点“重试”后从该关的满血起点重建敌人、机关和 KO 现场。例如第 11 关失败回第 09 关，第 14 关失败回第 13 关。最后一波清空后先完成约 3 秒收尾再进入过关/通关结果；中途玩家 KO（包括双 KO）仍立即失败。跨波次的倒地敌人保留各自剩余时间，换关/重试则清理尸体与散骨。刷新网页会从已记录的当前关卡起点重新开始，不能跳过失败后必须重打的关卡。

路线中已经通关的关卡可点击重打，未通关或锁定的关卡不能提前进入。重打是独立的临时练习：从选中关的起点开始，按“开始重打”开战，成功或失败后可点“再打这一关”或“返回主线”；右侧始终有“退出重打 · 返回主线”，练习中也可点另一已通关节点换关。退出后原正式战斗/结果现场恢复并暂停，确认“继续主线”再走动；练习中切到联机也会先退出练习、恢复正式现场。练习胜负不推进关卡、不增加正式失败次数、不改存档或已通关记录。通关全部 56 关后也能重打第 56 关，无须先重置记录。练习现场只在本次打开的页面内保存，刷新会回到正式记录对应的关卡起点。

闯关记录和正式过关取得的背包装备存于当前浏览器的 `localStorage`，不在多设备间同步。清除浏览器网站数据会清除存档和装备；当浏览器禁止本地存储时，本次打开期间仍可游玩，但刷新后无法保留进度。联机胜负不影响闯关存档。

### 照片背景

森林与城市各有 5 张、海洋与陆地各有 4 张裁剪压缩后的照片背景。原有的 16 张 WebP 均保留：第 01 关改用用户指定的 `pic/微信图片_20261004174959_18_2.jpg` 转制照片，原来的 `forest.webp` 移至第 04 关；第 27 关新增用户指定的 `pic/微信图片_20261004174956_16_2.jpg` 转制照片，其余原有照片关卡不变。共 18 关显示照片，彼此不相邻，每张照片只对应一个关卡；其余 38 关继续使用绘制场景。照片与关卡的对应关系固定，刷新、失败回档和重试后不会随机换图；平台、机关和碰撞规则不受背景影响。

照片仅在被选中的单人关卡按需加载，并轻柔渐入；若图片尚未加载或加载失败，画面自动保留对应主题的绘制背景。横向扩展的单人场地会把固定照片按视口宽度分屏并镜像延展，移动镜头时画面仍接续同一关的照片，不会重新随机选图。联机对战始终使用绘制场景，双方的对战画面和碰撞规则不受照片加载影响。公开目录 `public/assets/backgrounds/` 有 18 张去除 EXIF 拍摄信息的 1600×900 WebP；部分照片里仍能看到人物，**去除 EXIF 不等于人像匿名化**，分享游戏前应确认肖像及照片使用权。JPG 原件只保留在本机被 Git 忽略的 `pic/` 中，不随仓库上传，克隆后也无需原图即可运行。12 张 Wikimedia Commons 风景照片的来源与授权页见 [`BACKGROUND_DOWNLOADS.md`](BACKGROUND_DOWNLOADS.md)；该清单不涵盖已作为公开背景收录的用户提供照片，也不为玩家自行选择的本机头像作肖像授权证明。

## 联机规则

两名玩家加入同一房间后倒数三秒开赛，单局 99 秒。联机战场为 2880×540 逻辑像素（原来 960 宽的三倍），每人用 960×540 视口跟随本人，离屏对手可见方向提示；四主题绘制背景横向延展。服务端布置对称的浮台、旋转木条和可伤双方的主题地面陷阱；平台相位、机关启停、单次约最大生命 10% 的伤害均由服务端计算。两人对称出生在战场中段，以免开局就隔着整个场地。服务端以固定 60Hz 计算位置、碰撞、命中、血量和胜负；客户端发送带递增序号的按键状态，接收约 20Hz 的战斗快照，并对画面做有限平滑。双方都能用拳、踢、跳、闪、每局五发投矛和充能光波。KO 或倒计时结束时结算；双方都申请后才重赛，重赛重置技能余量与机关相位。对手断线时房主回等待，新玩家可加入；房主断线则房间关闭。联机不启用单人偶数关天降坠物、装备或尸体散骨。

## 项目结构与验证

- `shared/combat.js`：闯关与联机共用的确定性战斗模拟。
- `shared/equipment.js`：九件 Boss 保底装备的唯一目录和分层数值。
- `shared/levels.js`：四主题、56 关、存档点及逐步增加的楼梯/动态平台配置。
- `shared/platforms.js`：绘制、人物承载、碰撞和 AI 共用的动态平台姿态计算。
- `public/campaign.js`：单人波次、装备掉落/拾取与存档回滚、通关与失败回档，以及与正式存档隔离的已通关重打。
- `public/avatar.js`：本机图片校验、裁切/缩小及拍照帧处理，不传服务端。
- `public/app.js`、`render.js`、`styles.css`、`index.html`：输入、房间交互、画面、音效与响应式界面。
- `public/assets/backgrounds/`：森林、城市各 5 张，海洋、陆地各 4 张闯关照片背景；本机 `pic/` 中的 JPG 原件既不会被游戏服务公开，也不会进入 Git 仓库。
- `server/index.js`：静态资源和 WebSocket 房间服务。
- `test/`：关卡/存档、物理、网络房间、照片选图与资源接线测试。

本地自动化测试覆盖所有 56 关的配置与短时实战模拟、存档回退/刷新、攻击去重/闪避/平台/机关，以及两客户端 WebSocket 房间、同步、异常输入、超时、重赛和断线。它不代替跨设备的手感与网络压力测试。
