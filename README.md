# 线斗 · 火柴人竞技场

一款本地运行的网页版火柴人格斗游戏：56 关单人闯关，以及通过同一台游戏服务连接的实时 1v1 对战。无需账号或云端服务；场景照片随游戏一起存放在本地，音效由程序合成。

## 启动

需要 Node.js 20 或更新版本。在 PowerShell 中进入本目录，然后运行：

```powershell
npm install
npm start
```

浏览器打开 <http://127.0.0.1:3000/>。开发时可以运行 `npm run dev` 自动重启服务；自动化测试运行 `npm test`。如果你的受限终端阻止 Node 测试启动子进程，可用 `node --test --test-isolation=none`。

### 两台设备在同一局域网对战

在作为房主服务的电脑上运行：

```powershell
$env:HOST = '0.0.0.0'
npm start
```

两台设备都访问 `http://<服务电脑的局域网 IP>:3000/`。一方点“联机对战 → 创建对战房间”，把六位房间码给另一方；另一方输入房间码加入。若连接不上，检查两台设备能否访问同一局域网地址，以及服务电脑的防火墙是否放行 TCP 3000。端口冲突时先设 `$env:PORT = '3001'`，两台设备改用该端口。

服务默认只监听 `127.0.0.1`，不会自动公开到互联网。当前房间码没有账号认证，服务本身也没有 TLS；不要把裸 HTTP/WS 服务直接暴露到公网。公网对战需要另行部署到可访问的服务器，并配置 HTTPS/WSS 反向代理及访问防护。

## 操作与打击反馈

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动 | A / D 或左右方向键 | 左 / 右按钮 |
| 攻击 | J | 攻击按钮 |
| 踢腿 | K | 踢腿按钮 |
| 无敌光波（符合条件的闯关关卡） | L | 光波按钮 |
| 跳跃 | 空格 | 跳跃按钮 |
| 空中跳踢 | 跳起后在空中按 K | 跳起后在空中按踢腿按钮 |
| 闪避 | Shift | 闪避按钮 |

连续按攻击键可接三段挥拳，拳头周围出现弧形拳风，不再射出箭头；踢腿和空中跳踢也属于近身招式，每次出招对同一目标只结算一次。火柴人采用夸张的大头、细身和细肢比例；Boss 身形更高大、肩部更宽，出拳前有明显预警。敌人会判断你所在方向，绕到其背后时会先转身再出招，不再背对着人原地空挥。跳踢在有效攻击帧释放脚端能量、定向碎光、扩散环和短促震动；未命中也有完整动作，低动态设置会减弱尾迹与粒子。跳跃带有短暂的离地宽容和提前输入缓冲；闪避有约 0.18 秒无敌时间及约 0.9 秒冷却。战斗按固定 60 帧模拟重力、摩擦、单向平台、碰撞、击退和受击硬直。命中还会触发短暂停顿、粒子、合成音效与轻微镜头震动。角色被击倒时，烂番茄会从上方砸向头部并破裂，湿润的合成砸开声与落点同步；结果面板会短暂延后，让玩家看清这一幕，低动态模式缩短等待。音效开关同时控制番茄声；“真实感”来自这些可读的反馈，**不是三维刚体或布娃娃物理**。

单关敌人总数超过 3 名时，击倒每 2 名敌人可积攒 1 次光波；按 L 或触屏按钮释放，消耗 1 次充能，对当前波次所有存活敌人造成「剩余血量减半」（向上取整，光波本身不会直接击倒），同时让玩家约 0.6 秒无敌。充能仅统计玩家亲自击倒的敌人，不计机关击倒；未获得充能时不可释放，进入另一关后重新累计。光波仅限单人闯关，联机对战没有这个技能。

## 56 关与存档

| 关卡 | 场景 | 存档关 | 首领关 | 场景机制 |
|---|---|---|---|---|
| 01–14 | 森林 | 01、05、09、13 | 10、14 | 树冠、倒木平台、荆棘、偶数关松果坠落 |
| 15–28 | 城市 | 15、19、23、27 | 20、28 | 天际楼群、屋顶平台、交通危险区、偶数关碎片坠落 |
| 29–42 | 海洋 | 29、33、37、41 | 30、40、42 | 海面、码头/甲板平台、潮汐危险区、偶数关冰雹 |
| 43–56 | 陆地 | 43、47、51、55 | 50、56 | 荒原山峦、岩台、地裂危险区、偶数关碎石坠落 |

每关有自己的名称、敌人波次、敌人类型与强度、平台和机关配置。第 10、20、30、40、50 关在原有敌人波次之后追加一名 Boss，原来的章节 Boss（14、28、42、56 关）继续保留；进入 Boss 波前会恢复部分生命值。每个偶数关约每 4 秒预警并坠落一件主题小物体，一次只落一件；命中玩家或敌人会扣除其最大生命值约 10%，可通过走位或闪避躲开，奇数关与联机对战没有坠物。落点在预警时根据场上人物位置确定，之后不再追踪；相同操作下重试时序可复现。

进入存档关时自动激活存档；失败立即把进度写回最近的存档关，点“重试”后从该关的满血起点重建敌人和机关。例如第 11 关失败回第 09 关，第 14 关失败回第 13 关。刷新网页会从已记录的当前关卡起点重新开始，不能跳过失败后必须重打的关卡。

闯关记录存于当前浏览器的 `localStorage`，不在多设备间同步。清除浏览器网站数据会清除存档；当浏览器禁止本地存储时，本次打开期间仍可游玩，但刷新后无法保留进度。联机胜负不影响闯关存档。

### 照片背景

森林与城市各有 5 张、海洋与陆地各有 4 张裁剪压缩后的照片背景。原有的 16 张 WebP 均保留：第 01 关改用用户指定的 `pic/微信图片_20261004174959_18_2.jpg` 转制照片，原来的 `forest.webp` 移至第 04 关；第 27 关新增用户指定的 `pic/微信图片_20261004174956_16_2.jpg` 转制照片，其余原有照片关卡不变。共 18 关显示照片，彼此不相邻，每张照片只对应一个关卡；其余 38 关继续使用绘制场景。照片与关卡的对应关系固定，刷新、失败回档和重试后不会随机换图；平台、机关和碰撞规则不受背景影响。

照片仅在被选中的单人关卡按需加载，并轻柔渐入；若图片尚未加载或加载失败，画面自动保留对应主题的绘制背景。联机对战始终使用绘制场景，双方的对战画面和碰撞规则不受照片加载影响。公开目录 `public/assets/backgrounds/` 有 18 张去除 EXIF 拍摄信息的 1600×900 WebP；部分照片里仍能看到人物，**去除 EXIF 不等于人像匿名化**，分享游戏前应确认肖像及照片使用权。JPG 原件只保留在本机被 Git 忽略的 `pic/` 中，不随仓库上传，克隆后也无需原图即可运行。12 张 Wikimedia Commons 风景照片的来源与授权页见 [`BACKGROUND_DOWNLOADS.md`](BACKGROUND_DOWNLOADS.md)；该清单不涵盖用户上传照片的授权。

## 联机规则

两名玩家加入同一房间后倒数三秒开赛，单局 99 秒。服务端以固定 60Hz 计算位置、碰撞、命中、血量和胜负；客户端发送带递增序号的按键状态，接收约 20Hz 的战斗快照，并对画面做有限平滑。击倒或倒计时结束时结算；双方都申请后才开始重赛。对手断线时，房主的房间回到等待状态，可让新玩家加入；房主断线则房间关闭。

## 项目结构与验证

- `shared/combat.js`：闯关与联机共用的确定性战斗模拟。
- `shared/levels.js`：四主题、56 关和存档点的数据配置。
- `public/campaign.js`：单人波次、通关与失败回档。
- `public/app.js`、`render.js`、`styles.css`、`index.html`：输入、房间交互、画面、音效与响应式界面。
- `public/assets/backgrounds/`：森林、城市各 5 张，海洋、陆地各 4 张闯关照片背景；本机 `pic/` 中的 JPG 原件既不会被游戏服务公开，也不会进入 Git 仓库。
- `server/index.js`：静态资源和 WebSocket 房间服务。
- `test/`：关卡/存档、物理、网络房间、照片选图与资源接线测试。

本地自动化测试覆盖所有 56 关的配置与短时实战模拟、存档回退/刷新、攻击去重/闪避/平台/机关，以及两客户端 WebSocket 房间、同步、异常输入、超时、重赛和断线。它不代替跨设备的手感与网络压力测试。
