# 线斗 · 火柴人竞技场

一款本地运行的网页版火柴人格斗游戏：56 关单人闯关，以及通过同一台游戏服务连接的实时 1v1 对战。单人关卡在 1920×540 的横向场地中推进，画面用 960×540 视口跟随玩家；联机仍在固定 960×540 场地对战。无需账号或云端服务；场景照片随游戏一起存放在本地，背景音乐与战斗音效由程序合成。

详细的现行版关卡结构、操作机制、联机房间、失败重试、场景与验收口径见 [功能与内容 PRD](outputs/PRD-火柴人竞技场-20261004.md)。

协作者和 AI 助手请先看 [AI 协作约定](AGENTS.md) 与 [协作开发指南](CONTRIBUTING.md)；修改代码时参考 [架构与状态边界](docs/ARCHITECTURE.md)、[视觉与交互设计基线](docs/DESIGN_BASELINE.md) 和 [决策记录](docs/DECISIONS.md)，将新决定留在仓库而不只留在聊天记录中。

## 启动

需要 Node.js 20 或更新版本。在 PowerShell 中进入本目录，然后运行：

```powershell
npm install
npm start
```

浏览器打开 <http://127.0.0.1:3000/>。开发时可以运行 `npm run dev` 自动重启服务；自动化测试运行 `npm test`。如果你的受限终端阻止 Node 测试启动子进程，可用 `node --test --test-isolation=none`。

### 两台设备在同一局域网对战

在作为房主服务的电脑上运行：

```powershell
$env:HOST = '0.0.0.0'
npm start
```

两台设备都访问 `http://<服务电脑的局域网 IP>:3000/`。一方点“联机对战 → 创建对战房间”，把六位房间码给另一方；另一方输入房间码加入。若连接不上，检查两台设备能否访问同一局域网地址，以及服务电脑的防火墙是否放行 TCP 3000。端口冲突时先设 `$env:PORT = '3001'`，两台设备改用该端口。

服务默认只监听 `127.0.0.1`，不会自动公开到互联网。当前房间码没有账号认证，服务本身也没有 TLS；不要把裸 HTTP/WS 服务直接暴露到公网。公网对战需要另行部署到可访问的服务器，并配置 HTTPS/WSS 反向代理及访问防护。

## 操作与打击反馈

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动 | A / D 或左右方向键 | 左 / 右按钮 |
| 攻击 | J | 攻击按钮 |
| 踢腿 | K | 踢腿按钮 |
| 无敌光波（符合条件的闯关关卡） | L | 光波按钮 |
| 投矛瞄准 / 确认发射（仅单人闯关，每关最多 5 发） | I 首按瞄准、再次按 I 发射 | 投矛 → 发射按钮 |
| 瞄准时抬高 / 压低 | ↑ / ↓ 或 W / S（可按住微调） | 抬高 / 压低按钮，或在舞台上下拖动 |
| 取消未确认的瞄准 | Esc | 取消按钮 |
| 跳跃 | 空格 | 跳跃按钮 |
| 空中跳踢 | 跳起后在空中按 K | 跳起后在空中按踢腿按钮 |
| 闪避 | Shift | 闪避按钮 |

可操控的火柴人采用深色侠客造型：宽檐、破边且有编织纹理的蓑帽，暗色大头与可辨情绪的亮眼，颈部围巾和随走动、跳跃、停步改变形态的披风。P1 披风偏赤红，联机 P2 使用清晰不同的冷色；普通敌人和 Boss 保持原造型。这是对用户所给侠客图片的游戏内简化演绎，不直接收录原图，也没有新增持刀攻击。服饰只影响画面，不改变命中或碰撞。

连续按攻击键可接三段挥拳，拳头周围出现弧形拳风，不再射出箭头；踢腿和空中跳踢也属于近身招式，每次出招对同一目标只结算一次。火柴人采用夸张的大头、细身和细肢比例；胜利时露出开心表情、被击败时露出伤心表情，连续挥拳中有努力发力的神情。Boss 身形更高大、肩部更宽，出拳前有明显预警。敌人会判断你所在方向，绕到其背后时会先转身再出招；玩家位于正上方时会继续追踪并寻找可命中的位置，不在高度分离时机械空挥。中后期敌人也可能投矛，但会先有可辨前摇。跳踢在有效攻击帧释放脚端能量、定向碎光、扩散环和短促震动；未命中也有完整动作，低动态设置会减弱尾迹与粒子。跳跃带有短暂的离地宽容和提前输入缓冲；闪避有约 0.18 秒无敌时间及约 0.9 秒冷却。战斗按固定 60 帧模拟重力、摩擦、单向平台、碰撞、击退和受击硬直。命中还会触发短暂停顿、粒子、合成音效与轻微镜头震动。角色被击倒时，烂番茄从上方加速砸向头部，先压扁再破裂，汁液向两侧飞溅并短暂留在头顶；湿润的合成砸开声与落点同步。单人敌人还会倒地，约 0.45 秒落稳后留在地上约 3 秒；玩家先离开，再站在尸体同一实际地面或同一块平台（包括移动、倾斜木条）上走过，尸体才会散成骨头并提前消失。隔着一块浅木板、仅看起来脚底接近不会触发。踩骨只提供反馈，不伤人也不额外积攒光波。若这是本关最后一名敌人，KO 后会有约 3 秒可左右移动和跳跃、免伤的收尾时间供玩家走过去；进入收尾时先前短按缓存的拳/踢/闪不会突然执行，普通攻击、踢腿、闪避、投矛与光波此时不可用。临近结束踩到骨头时会短暂等动效显示完再出现过关结果；自己被 KO 或双方同时 KO 仍按失败处理。暂停和打击停顿不计入这些有效战斗帧。低动态模式减少番茄飞溅与散骨运动，但保留砸中、污渍、骨头散开的关键线索和胜负反馈。联机仍有 KO 番茄，但没有踩骨。音效开关同时控制番茄声和散骨声；“真实感”来自这些可读的反馈，**不是三维刚体或布娃娃物理**。

“灵能武侠”声画升级让真正命中时出现短促白金墨锋与随森林、城市、海洋、陆地微调的碎光；跳踢以脚端玉色弧光为重点，光波从侠客身前聚能并朝面向方向打出玉白主光束，伴随较弱的环形余波和目标命中亮点，Boss 拳部聚起金色蓄势，避免整屏连续闪白。拳脚命中有破风与着肉的分层合成声，跳踢、光波和投矛各有音色；空挥拳不播放命中声。混音限制同时发声数量，静音或切换场景会清除待播尾音。减少动态效果时保留短促的定向光束、静态命中轮廓和 Boss 预警，但不震屏或播放长尾迹；这些效果不改变攻击范围、伤害和联机胜负。

背景音乐在森林、城市、海洋、陆地各有一段低音量合成循环，不需要额外下载音乐文件。单人只在战斗与末敌收尾时播放；联机只在正式对战时播放，使用房主选定的主题，等待、倒数和结算期间不循环。首次播放须先有浏览器允许的点击/按键等用户手势；页头“声音”开关同时控制音乐和打击音效。命中或 KO 时音乐短暂让位，拳脚着肉、光波和番茄等反馈保持更突出；关闭声音、页面失焦/隐藏或离开战斗时停止音乐，恢复焦点后仅在仍处于可播放的战斗阶段时继续。音量在不同扬声器、耳机和手机上仍需实际试听，不能仅凭自动化测试宣称混音已验收。

单人敌人追击玩家时会主动识别前方地面陷阱并尝试跳过或避开；即使被击退到陷阱附近，恢复追击后也不应机械地反复冲入同一区域受伤。这是敌人的路线选择，不是对陷阱伤害的免疫：实际碰上仍按原有规则扣血，玩家所受伤害和联机 PvP 规则不变。预判、起跳、安全落点及周期机关暂时等待的细节是本版实现选择，并非额外按键。

单人投矛与拳风是不同招式：拳风始终贴近拳头。可出招时第一次按 I（触屏点“投矛”）进入瞄准，角色面向的前方最近敌人只用于估算初始角度；前方没有合适敌人时默认为 42°，**不会自动锁定或追踪目标**。舞台出现随人物位置、朝向和角度更新的抛物线与预计落点；按 ↑/↓ 或 W/S 抬高/压低（8°–72°），瞄准期间仍可用左右方向键或 A/D 走位、转身。再次按 I（触屏点“发射”）确认角度与朝向，随后蓄势约 20 个有效战斗帧再投出。投矛以固定速度沿确认的方向受重力飞行；由于玩家的惯性、移动平台、敌人走位及遮挡，显示的预计落点只是**当前起点的理论参考**，并不保证命中。触屏还可在舞台上竖向拖动调角，松手不会自动发射，需点“发射”。

Esc 或触屏“取消”退出未确认的瞄准；在瞄准中按攻击、踢腿、跳跃或闪避会取消瞄准并照常尝试该动作，受击/KO、切模式、暂停或页面失焦也会退出瞄准。若关卡允许光波、有充能且当前波存在活敌人，瞄准或蓄势中按 L/触屏“光波”会立即发动并打断投矛；无充能或不可发动时不会取消瞄准。已确认的蓄势不会被 Esc、失焦、暂停或切模式倒退，但受击或成功发动光波会打断本次发射；蓄势中不能主动左右移动或叠加拳脚/跳/闪。玩家投矛**每关最多 5 发、不依赖 KO 充能、无额外冷却**：进入瞄准、确认蓄势、取消或蓄势被打断均不扣，真正投出时才扣 1 发；各波共用本关余量，进入下一关或失败回存档重试后重置为 5 发，余量为 0 时不能再瞄准。投出后松开并重新按 I 可继续瞄准，按住不会连发。第 15 关起部分普通敌人仍按原有节奏自动锁定玩家当时位置、预警后投矛；敌我双方都可走位、借平台遮挡或闪避。联机没有投矛，也不向房间服务发送投矛输入。

单关预设敌人总数超过 3 名时，击倒每 2 名敌人可积攒 1 次光波；按 L 或触屏按钮释放，消耗 1 次充能，对当前波次所有存活普通敌人造成「剩余血量减半」、对 Boss 造成「剩余血量减去三分之一」（即剩余 `ceil(原 HP × 2/3)`），均向上取整，光波本身不会直接击倒，同时让玩家约 0.6 秒无敌。画面以朝人物面向方向射出的主光束为核心，环形余波和各目标命中线索说明**当前波所有存活敌人**均受影响，包括人物身后的敌人；主光束不是新增的狭窄碰撞判定。Boss 召唤的小兵不计入开关资格所用的预设人数；玩家亲自击倒它们仍可累计光波，机关/坠物击倒不计。未获得充能时不可释放，进入另一关后重新累计。光波仅限单人闯关，联机对战没有这个技能。

## 56 关与存档

| 关卡 | 场景 | 存档关 | 首领关 | 场景机制 |
|---|---|---|---|---|
| 01–14 | 森林 | 01、05、09、13 | 10、14 | 树冠、倒木平台、荆棘、偶数关松果坠落 |
| 15–28 | 城市 | 15、19、23、27 | 20、28 | 天际楼群、屋顶平台、交通危险区、偶数关碎片坠落 |
| 29–42 | 海洋 | 29、33、37、41 | 30、40、42 | 海面、码头/甲板平台、潮汐危险区、偶数关冰雹 |
| 43–56 | 陆地 | 43、47、51、55 | 50、56 | 荒原山峦、岩台、地裂危险区、偶数关碎石坠落 |

每关有自己的名称、敌人波次、敌人类型与强度、平台和机关配置。第 8 关起出现机动跳袭的「跃袭者」，第 18 关起出现抛小石的远程「石掷手」；它们替换预设波次中的部分常规兵位，不凭空增加每关预设人数。石掷手使用自己的小石，不叠加旧敌人的投矛。每章从三阶楼梯起步，第 4 关位起增加楼梯高度，第 5 关位起有上下浮动台阶，第 6 关位起增加另一组楼梯，第 8 关位起出现旋转木条，第 11 关位起第二个浮台改为左右漂移（章内 11–14 关位分别为 ±20/24/28/32 逻辑像素），第 13 关位再加入木条；浮台移动、碰撞与人物承载同步，首关没有动态平台或地面机关。第 10、20、30、40、50 关在原有敌人波次之后追加一名 Boss，原来的章节 Boss（14、28、42、56 关）继续保留；进入 Boss 波前会恢复部分生命值。五位里程碑 Boss 随关数逐级累加投石、召唤小兵、震地、双石连投和短暂护体；召唤仅在 Boss 存活时发生，同场最多 5 名活召唤兵。章节 Boss 保持既有拳法定位。每个偶数关约每 4 秒预警并坠落一件主题小物体，一次只落一件；命中玩家或敌人会扣除其最大生命值约 10%，可通过走位或闪避躲开，奇数关与联机对战没有坠物。落点在预警时根据场上人物位置确定，之后不再追踪；相同操作下重试时序可复现。

进入存档关时自动激活存档；失败立即把进度写回最近的存档关，点“重试”后从该关的满血起点重建敌人、机关和 KO 现场。例如第 11 关失败回第 09 关，第 14 关失败回第 13 关。最后一波清空后先完成约 3 秒收尾再进入过关/通关结果；中途玩家 KO（包括双 KO）仍立即失败。跨波次的倒地敌人保留各自剩余时间，换关/重试则清理尸体与散骨。刷新网页会从已记录的当前关卡起点重新开始，不能跳过失败后必须重打的关卡。

闯关记录存于当前浏览器的 `localStorage`，不在多设备间同步。清除浏览器网站数据会清除存档；当浏览器禁止本地存储时，本次打开期间仍可游玩，但刷新后无法保留进度。联机胜负不影响闯关存档。

### 照片背景

森林与城市各有 5 张、海洋与陆地各有 4 张裁剪压缩后的照片背景。原有的 16 张 WebP 均保留：第 01 关改用用户指定的 `pic/微信图片_20261004174959_18_2.jpg` 转制照片，原来的 `forest.webp` 移至第 04 关；第 27 关新增用户指定的 `pic/微信图片_20261004174956_16_2.jpg` 转制照片，其余原有照片关卡不变。共 18 关显示照片，彼此不相邻，每张照片只对应一个关卡；其余 38 关继续使用绘制场景。照片与关卡的对应关系固定，刷新、失败回档和重试后不会随机换图；平台、机关和碰撞规则不受背景影响。

照片仅在被选中的单人关卡按需加载，并轻柔渐入；若图片尚未加载或加载失败，画面自动保留对应主题的绘制背景。横向扩展的单人场地会把固定照片按视口宽度分屏并镜像延展，移动镜头时画面仍接续同一关的照片，不会重新随机选图。联机对战始终使用绘制场景，双方的对战画面和碰撞规则不受照片加载影响。公开目录 `public/assets/backgrounds/` 有 18 张去除 EXIF 拍摄信息的 1600×900 WebP；部分照片里仍能看到人物，**去除 EXIF 不等于人像匿名化**，分享游戏前应确认肖像及照片使用权。JPG 原件只保留在本机被 Git 忽略的 `pic/` 中，不随仓库上传，克隆后也无需原图即可运行。12 张 Wikimedia Commons 风景照片的来源与授权页见 [`BACKGROUND_DOWNLOADS.md`](BACKGROUND_DOWNLOADS.md)；该清单不涵盖用户上传照片的授权。

## 联机规则

两名玩家加入同一房间后倒数三秒开赛，单局 99 秒。服务端以固定 60Hz 计算位置、碰撞、命中、血量和胜负；客户端发送带递增序号的按键状态，接收约 20Hz 的战斗快照，并对画面做有限平滑。击倒或倒计时结束时结算；双方都申请后才开始重赛。对手断线时，房主的房间回到等待状态，可让新玩家加入；房主断线则房间关闭。

## 项目结构与验证

- `shared/combat.js`：闯关与联机共用的确定性战斗模拟。
- `shared/levels.js`：四主题、56 关、存档点及逐步增加的楼梯/动态平台配置。
- `shared/platforms.js`：绘制、人物承载、碰撞和 AI 共用的动态平台姿态计算。
- `public/campaign.js`：单人波次、通关与失败回档。
- `public/app.js`、`render.js`、`styles.css`、`index.html`：输入、房间交互、画面、音效与响应式界面。
- `public/assets/backgrounds/`：森林、城市各 5 张，海洋、陆地各 4 张闯关照片背景；本机 `pic/` 中的 JPG 原件既不会被游戏服务公开，也不会进入 Git 仓库。
