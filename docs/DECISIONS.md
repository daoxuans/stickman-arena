## 新决定的最小记录格式

```markdown
### D-下一编号 · 简短标题

- 录入日期：YYYY-MM-DD
- 性质与状态：用户明确确认 / 现行实现 / 建议待确认 / 已废弃
- 决定：一句可以核验的规则；适用模式、关卡、状态、例外。
- 理由与取舍：为什么采用，明确舍弃什么。
- 影响：页面、关卡/存档、联机、素材、测试、PRD 和设计基线中的哪些部分。
- 证据：用户确认记录或仓库变更/测试链接。
```

提出新想法时先标“建议待确认”，不要直接改成“用户明确确认”。决定被替换时保留原记录并标明新编号，避免后续 AI 只看到最新结果却不知道为何变化。
