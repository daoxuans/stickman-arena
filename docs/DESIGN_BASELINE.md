# 视觉与交互设计基线（当前实现）

这是从 [页面](../public/index.html)、[样式](../public/styles.css) 和 [画面绘制](../public/render.js) 归纳的**现行基线**，用于让下一位开发者/AI 延续已有风格；它不是用户签字的品牌规范，也不宣称通过真实设备视觉或无障碍验收。玩法、字段与状态以 [PRD](../outputs/PRD-火柴人竞技场-20261004.md) 为准。

## 体验与视觉层级

- 品牌用“线斗 / STICK ARENA”：倾斜三笔的 CSS 图形、中文主字标和紧凑英文辅助标。不要无缘由换成图片商标或另一套命名。
- 战斗画面优先占据首屏；舞台外是深墨绿框架，右侧路线/房间操作放在浅矿物纸色面板。当前任务一眼先看对战，再看进度或房间操作。
- 暖橙为主操作、当前关和 P1 提示；珊瑚红区分对手及部分警示，机关仍按各主题使用自己的色彩；四主题绘制场景分别采用森林蓝绿、城市紫灰、海洋青蓝、陆地赭石。场景调色不等于整站切换四套 UI 主题。
- 角色是“大头、细身、细肢”的火柴人；当前绘制普通头半径约 22 个逻辑像素，肢体核心描边多为 4.2–4.8，Boss 保持火柴人骨架但整体视觉约放大 1.28 倍并加宽肩线。这些是已实现比例，改变时应同时检查受击范围与反馈。

## 布局与组件语义

| 区域/组件 | 当前规则 | 保持一致时的关注点 |
|---|---|---|
| 总体 | 内容最大宽度 1800px；页头放品牌、居中的双模式页签和会话/音效；主区左舞台自适应、右面板约 296–342px。 | 两模式共用舞台外壳；右面板、舞台画面、标题、HUD 与覆盖层须按模式同步更新，且舞台保持主视觉地位。 |
| 舞台 | Canvas 逻辑 960×540、CSS 维持 16:9；顶部叠放 P1/P2 血条和波次/时间，状态覆盖层覆盖画面。 | HUD 左右身份、波次与时间含义不能混；覆盖层不制造与真实状态相反的操作。 |
| 路线/房间面板 | 浅纸色、高对比深字；路线 7 列数字节点，当前/存档/Boss/已通关/锁定有不同标记。 | 路线是进度提示而非可跳关导航。 |
| 按钮 | 暖橙主按钮、深色次按钮、描边/安静按钮；禁用有低不透明度；模式选中有底部暖橙强调线。 | 强调只给当前主要行动；不可用动作要禁用或清楚解释。 |
| 细节 | 直线、画框角线、斜切笔画、存档菱形为几何语言；地图格仅轻微圆角。 | 不要误读为“全站禁用圆形”：人物头、光波和装饰环本来就是圆形。 |

响应式现状：宽度 ≤1100px 主区上下堆叠；≤760px 页头折行、键盘提示隐藏并显示触控按键；≤540px HUD 隐藏生命数字但保留血条；≤360px 进一步压缩标题与按钮；粗指针设备即使宽度 >760px 也显示触控。页面声明最小宽度 320px，不代表更窄设备经过验收。

## 动作与反馈的视觉语法

| 动作/事件 | 当前表现 |
|---|---|
| 拳击 | 有效帧在拳头附近出现弧形拳风；没有光箭、远程投射物。三段出拳节奏不同。 |
| 地面踢/跳踢 | 脚端能量；空中跳踢在有效帧出现碎光、扩散环与短促震屏，空挥仍有完整动作。 |
| 闪避/落地/命中 | 闪避残影、落地扬尘；拳脚命中有高亮、粒子、击退及 4–7 帧打击停顿，地面机关的停顿更短。 |
| Boss/光波/坠物 | Boss 更高大且有拳击预警；符合条件的闯关光波有扩散与无敌轮廓；偶数关坠物先有可辨预警。 |
| KO | 每名被 KO 角色头顶落一颗烂番茄并破裂，音效与砸开时点同步；结果覆盖层稍后出现。 |
| 照片 | 18 个固定单人关按需加载，准备好后约 250ms 渐入；缺图保留绘制背景，联机永远不用照片。用户明确固定的第 01 关照片、当前放在第 27 关的另一张用户要求保留的照片，都不得在普通改样式时被替换或遮蔽；第 27 关号是现行选位。 |

系统偏好 `prefers-reduced-motion: reduce` 会把 CSS 动画/过渡压至接近零、取消 Canvas 震屏及部分拳风/坠物/跳踢的附加尾迹并减少粒子；闪避残影和关键动作线索仍保留，因此不是“完全静态模式”。当前舞台入场约 0.48s、模式颜色过渡约 0.18s、按钮/节点悬停约 0.16s；新动效应有相应减少动态的处理。

## 可访问性现状与设计变更检查

当前已有中文页面语言、语义区域、输入标签、Canvas 的 `aria-label` 与不支持 Canvas 时的回退句、状态播报、模式与声音的按下状态、按钮/输入的自定义可见焦点。下拉选择框目前不在该自定义焦点规则内。**尚未证明** Canvas 战斗可全程读屏、覆盖层有完整焦点管理、所有文本对比度达到某一 WCAG 等级、所有手机触控都顺手或光敏安全阈值已测。

做有意的 UI/视觉调整时，建议在变更说明中附：改动前后桌面与 ≤540px 画面、闯关/联机两个模式、正常/减少动态两种设置；逐项核对主操作、HUD 可读性、房间错误与结果状态、当前第 01/27 关照片以及键盘焦点。没有实机或截图就标为未验证，不要用“设计已验收”概括。

PRD §4.4 的房间过期残留和加入者主题下拉错显是当前缺陷，不是要延续的交互风格。若确需重塑品牌或布局，请先和项目所有者确认新方向，再更新本基线、PRD 与相关测试。
