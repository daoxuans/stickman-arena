## 1. 产品说明

### 1.1 产品目标

让玩家在一台本地游戏服务提供的网页中完成 56 关单人闯关，或通过六位房间码进行实时双人对战。闯关以可读的近身动作、受击反馈、四主题场景和失败回档为核心；联机以同一房间内两名玩家的公平判定与明确的重赛/离房状态为核心。

### 1.2 用户角色

| 角色 | 核心诉求与范围 |
|---|---|
| 闯关玩家 | 从浏览器记录的当前关开始挑战；查看路线、血量、波次与存档；失败后从最近存档重试。 |
| 房主（P1） | 选择四种主题之一、创建房间、分享房间码、迎接一名对手；对手离开后可沿用房间。 |
| 加入者（P2） | 输入房主提供的六位码加入空房间，按房主选择的主题对战。 |

同一人可在不同时间担任以上角色；当前没有账户、管理员、观战者或第三名对战者。

### 1.3 信息组织原则

1. 顶部只按玩家目标提供两个模式入口：“闯关战役”和“联机对战”；打开网页默认进入闯关模式。页头会话状态和音效开关为两模式共用能力，不另设一级菜单。
2. 舞台是首要信息区：主题/标题、双方生命、当前波次或剩余秒数和战斗画面始终围绕舞台呈现；右侧只承载当前模式的路线或房间操作。
3. 闯关路线用 56 个节点显示进度与标记。节点提供说明性提示，不是可跳转的选关列表；实际推进只能通过覆盖层上的开始、重试或下一关动作完成。
4. 加入、倒计时、失败、过关、结算、断线等短时状态在同一舞台覆盖层表达；覆盖层的操作与右侧面板的按钮都必须指向同一实际房间/闯关状态。
5. 存档、光波次数、房间码等关键字段直接呈现，不藏在二级详情页；双方血量在宽屏显示数字与血条，宽度不超过 540px 时为节省空间只显示血条。联机 HUD 固定 P1/P2 左右顺序，以“你”标出当前身份，不交换血条位置。
6. 单人闯关记录与联机房间互不影响。切换到联机时暂停当前闯关现场；退出联机后返回闯关并显示对应阶段的覆盖层（战斗中才显示继续，失败/过关/通关显示各自操作）；刷新网页只恢复记录的关卡起点，不恢复战斗中的现场。

### 1.4 本版范围与边界

| 优先级 | 已有能力 | 边界 |
|---|---|---|
| P0 | 56 关、四章、16 个存档点、9 个 Boss 关、波次与难度变化 | 不支持点路线图跳关；通关后只能确认重开。 |
| P0 | 移动、三段拳、地面踢、空中跳踢、跳跃、闪避、条件式光波 | 光波只属于符合条件的单人关卡，联机没有光波。 |
| P0 | 敌人转向与差异化出招、平台/地面机关、偶数关坠物、失败回档 | 机关击倒敌人不计入玩家光波充能。 |
| P0 | 两人房间码对战、倒计时、计时结算、双方同意重赛、离房/断线反馈 | 没有账号认证、断线续局、旁观、联机战绩或持久房间。 |
| P0 | 第 01 关固定保留用户指定的 `forest-intro.webp`；另一张用户要求保留为某一关背景的照片，现行版以 `city-5.webp` 固定放在第 27 关 | 第 27 关是现行实现选位，并非用户指定的关号；回档、刷新或重试不能换掉现行关卡映射，肖像/来源许可仍待核实。 |

| P1 | 触屏控制、减少动态效果、复制房间码失败时的手动复制回退 | 不表示已经完成所有设备和辅助技术的实机验收。 |

本版不含账号与云存档、排行/匹配、跨房间观战、背包/付费、手柄、自定义键位、独立暂停键、公网服务部署、HTTPS/WSS 或生产级容量承诺。网站数据被清除会失去本浏览器存档；服务默认仅监听本机地址，若在局域网开放服务，需要用户另行配置网络与防火墙。不要把当前无认证的 HTTP/WS 服务直接暴露到公网。

### 1.5 术语与统计口径

| 术语/字段 | 口径 |
|---|---|
| 关卡 | 1–56 的唯一编号；每关有章内关位、名称、主题、敌人波次、平台和机关。 |
| 波次 | 同波的敌人一起出现，全部击倒后才进入下一波；HUD 的“第 x/y 波”是关内波次，不是倒计时。 |
| 全关敌人总数 | 该关所有波次的敌人数量之和，包括追加的 Boss，不是场上即时存活数。 |
| 存档点 | 每章第 1、5、9、13 关；进入该关立即激活。失败返回最近已激活存档，死在存档关则重试该关。 |
| 当前进度 | 下次应进入的关卡编号；失败时立即改写为存档关，过关时变为下一关。 |
| 已通关记录 | 已击破关卡编号集合，用于通关显示；即使历史上通关，失败后超出当前进度的关卡也不能跳入。 |
| 累计失败次数 | 闯关玩家被击倒后递增 1；联机胜负不计入。 |
| 光波充能 | 符合资格的单关内，每由玩家亲自击倒两名敌人增加 1 次，按次数消耗；换关或重试清零。 |

## 2. 一级菜单与逻辑页面结构

| 一级入口 | 逻辑页面/状态 | 页面类型与选型理由 | 页面定位 | 优先级 |
|---|---|---|---|---|
| 闯关战役 | 闯关舞台与路线 | 战斗工作台：持续同时看动作、生命、波次和路线，比列表/详情页适合即时操作 | 进入和推进当前关卡 | P0 |
| 闯关战役 | 准备/失败/过关/全部通关覆盖层 | 状态操作层：单个明确决定控制继续、回档或重开 | 处理关卡状态转换 | P0 |
| 联机对战 | 房间面板/大厅 | 轻量创建与加入表单：房号、主题、房间状态与操作在舞台旁直出 | 创建或加入两人房间 | P0 |
| 联机对战 | 等待/倒计时/战斗/结果/断线覆盖层 | 状态操作层：不中断舞台上下文地表达房间生命周期 | 开赛、结算、重赛和恢复大厅 | P0 |

这些是一个网页中的两个页签及其状态，不设独立详情页、总览仪表盘或可浏览的关卡选择页面。页头音效开关、舞台 HUD、键盘/触控提示和轻提示为跨入口关联能力。

#### 3.1.3 交互与跳转

| 起始动作 | 页面反馈与目标状态 |
|---|---|
| 初次打开或刷新 | 读取本浏览器进度，重建其当前关的满血起点，显示“开始挑战/继续征程”覆盖层；已全部通关时显示通关覆盖层。 |
| 点击开始/继续 | 隐藏覆盖层并进入该关战斗；不跳过当前关。 |
| 点击任一路线节点 | 仅提示当前关、未到达或不可跳关；不改变关卡、存档或血量。 |
| 击倒当前波全部敌人 | 若尚有下一波则补血并进入下一波；无下一波且玩家仍存活则进入过关/通关覆盖层。 |
| 玩家生命归零 | 同帧先判失败，写回最近存档，展示失败覆盖层；即使最后一击同时击倒了敌人也不算过关。 |
| 点击“联机对战” | 暂停本次闯关现场，显示联机房间面板；该操作本身不修改闯关存档。 |

#### 3.2.1 页面信息

| 项目 | 内容 |
|---|---|
| 页面类型 | 覆盖舞台的状态操作层。 |
| 选型理由 | 开始、失败、过关只需单个决策和简短结果，不应离开舞台。 |
| 页面定位 | 告知本关所处阶段，并给出当前可执行的唯一推进动作。 |
| 布局结构 | 舞台画面上方的标题、说明与主操作按钮；通关重开另有确认。 |

#### 3.2.2 页面内容与动作

| 状态 | 标题/说明中的字段 | 主操作与结果 |
|---|---|---|
| 准备/继续 | 当前关编号、主题、关卡名、基础操作；符合资格时说明光波充能规则 | “开始挑战”进入战斗；本次网页会话切回闯关时可继续先前暂停的现场。 |

#### 3.2.3 交互与跳转

`准备 → 战斗 →（下一波 → 战斗）/失败/过关/全部通关`。失败只能经重试回最近存档；过关只能进入下一关；全部通关没有单关重玩入口。结果覆盖层会为 KO 番茄动效短暂让出观看时间，不能据此把战斗现场当成已持久保存。

### 3.3 关卡结构与难度规则

#### 3.3.1 四章与存档/Boss 布局

| 章 | 关卡编号 | 存档关 | Boss 关 | 主题 |

| 1 | 01–14 | 01、05、09、13 | 10、14 | 森林 |
| 2 | 15–28 | 15、19、23、27 | 20、28 | 城市 |

#### 3.3.2 地面与天空危险物

| 规则 | 内容 |
|---|---|
| 平台/地面机关 | 各关配置对应主题的单向落地平台；各章第 1 关位没有地面危险区，其余关按关位出现主题机关，部分按周期启停。玩家和敌人均受实际碰撞/伤害规则约束。 |
| 坠物准入 | 仅 28 个偶数关；奇数关和联机对战没有。森林为松果、城市为碎片、海洋为冰雹、陆地为小石块。 |
| 时序与密度 | 战斗约第 120 个有效帧首次预警，此后每 240 个有效帧出现一件；同一时刻只落一件。约 40 帧预警，接着约 30 帧坠落；命中停顿期间该时钟不推进。 |
| 落点与结算 | 预警时依据场上存活人物确定落点，之后不跟随；可走位避开。每件坠物最多命中一人，该人可能是玩家或敌人；命中者扣自身最大生命的 10%（四舍五入），闪避/无敌期间免伤。 |

#### 3.3.3 光波资格与结算

只有全关敌人总数 **大于 3** 的关卡开放光波，共 29 关，首次为第 07 关。满足条件的玩家亲自 KO 两名敌人得到 1 次可累积充能；机关/坠物造成的 KO 不计。按 L 或触控光波消耗 1 次，对**当前波**所有尚存活敌人分别使 `剩余 HP = ceil(原剩余 HP / 2)`；该招本身不会直接 KO，同时给予玩家约 36 个有效战斗帧无敌。空充能不能发动，长按不能连耗；进入下一关、失败重试或开新局均清零。第 30 关虽有 Boss，但合计只有 3 名敌人，所以没有光波；联机对战始终没有此技能。

### 3.4 操作、战斗结算与表现

#### 3.4.1 输入与招式

| 动作 | 键盘 | 触控 | 可观察规则 |
|---|---|---|---|
| 左右移动 | A/D 或左右方向键 | 左/右 | 有惯性、地面摩擦；失去窗口焦点或切后台释放按住的输入。 |
| 挥拳 | J | 攻击 | 可在衔接窗口接三段；基础伤害依次为 9/11/17，动作约 22/24/31 帧，再乘角色伤害倍率；拳风附着拳头，有弧线气流，**不发射箭头**。 |
| 踢腿 | K | 踢腿 | 地面近身踢约 20 帧、基础伤害 11；在空中变为约 26 帧、基础伤害 16 的跳踢，一次起跳最多一次，落地重置。 |
| 跳跃 | Space | 跳跃 | 重力与平台落地；离地宽限约 6 帧、提前输入缓冲约 8 帧。 |
| 闪避 | Shift | 闪避 | 约 11 帧位移和无敌，冷却约 54 帧；出招或受击硬直期间不能强行触发。 |
| 无敌光波 | L | 光波 | 仅 §3.3.3 所述单人关卡、充能大于零时可用；联机隐藏。 |

出招按“新按下”触发而不是按住自动连发；短按在受击停顿期间可保留到下一个有效帧。跳跃与踢腿同帧按下时先离地再判空中踢。近身命中同时检验朝向、攻击范围和纵向重叠；每次出招对同一目标最多伤害一次。拳/踢命中造成血量变化、打断、击退/挑起、硬直、短暂无敌与 4–7 帧打击停顿；地面机关的停顿更短，坠物/光波不套用这段拳脚停顿。双方同帧命中可互换伤害。KO 后该角色头顶会落下并破裂一颗烂番茄，结果面板略延后，让过程可见。

#### 3.4.2 画面、声音与敌人行为

普通火柴人强调大头、细躯干和细肢；Boss 更高大、肩宽并保有同一火柴人造型语言。拳头有效帧有拳风，踢腿有脚端能量，空中跳踢有定向碎光和扩散环；闪避有残影，落地有扬尘，重击有粒子与短促震屏，受击有高亮。音效随拳击命中、踢腿动作、跳跃、闪避、光波、坠物命中、KO 番茄、过关/失败等事件触发；未命中的空挥拳没有独立挥拳声。音效开关一并控制番茄声。减少动态效果偏好会降低粒子、尾迹和震屏，并停止装饰性 CSS 动画。

敌人依据场上玩家的位置追踪和转向；在允许转向且双方未高度重叠时先面向玩家再出拳，不会长期背对玩家原地空挥。攻击过程中锁定朝向以保留可读前摇，极近距离不持续左右抖动。不同敌种有不同节奏：疾行者更主动追击/跳跃，普通敌人偶尔踢腿，Boss 的强力拳有预警且不踢腿。当前没有视野遮挡、搜寻或侦测半径规则。这里的“物理感”指固定步长重力、摩擦、单向平台、碰撞、击退和受击停顿，**不等于三维刚体或布娃娃模拟**。

## 4. 联机对战

### 4.1 房间面板/大厅

#### 4.1.1 页面信息

| 项目 | 内容 |
|---|---|
| 页面类型 | 舞台旁的轻量创建/加入表单和房间状态面板。 |
| 选型理由 | 一人建房、一人输入编号，字段少且需要同时查看房间状态和舞台预览，无须多步向导。 |
| 页面定位 | 面向房主和加入者，完成选择主题、创建/加入、复制、退出和申请重赛。 |
| 布局结构 | 保留顶部模式入口与主舞台，右侧由闯关路线切换为房间面板；战斗阶段舞台叠加状态覆盖层。 |

#### 4.1.2 页面内容

| 模块 | 字段、枚举和校验 | 页面状态 |
|---|---|---|
| 房间说明 | 两人访问同一游戏服务地址、房主分享六位数字码、双方到齐自动倒计时 | 无账户/公网匹配入口。 |
| 我的房间编号 | 六位数字码；未入房显示占位；“复制”按钮 | 只有已入房才有可复制的有效编号。复制失败则自动选中输入框里的房号，提示手动复制。 |

|---|---|
| 房主选主题、点击创建 | 校验未在另一房间；生成六位码并成为 P1；显示“房间已建立/等待朋友加入”覆盖层。 |

### 5.2 响应式与减少动态效果

桌面以战斗舞台和右侧路线/房间面板并列；窄屏改为上下排列；触控场景显示大按钮，键盘提示可在小屏收起，宽度 ≤540px 时隐藏生命数字但保留双方血条。页面有画布说明、表单标签、按钮标签、状态播报和可见焦点样式。系统启用“减少动态效果”时减少粒子、尾迹和震屏，但核心命中、生命变化和胜负仍可辨。现有代码未证明全程读屏可玩、所有手机手感或低端设备帧率，这些不能写为已验收事实。

| 双方倒计时 | 倒数结束 | 联机战斗 | 战斗输入开始生效。 |
| 联机战斗 | KO/时间结束 | 结果覆盖层 | 显示赢家/平局与原因。 |
| 结果覆盖层 | 仅一人申请再战 | 再战等待覆盖层 | 保持结束态，显示 1/2。 |
| 结果/再战等待 | 双方申请再战 | 双方倒计时覆盖层 | 新一局满血重建。 |
| 联机房间 | P2 离开/断线 | P1 等待、新 P2 可加入；P2 大厅 | 保留房主原房码。 |
| 联机房间 | P1 离开/断线 | P2 房间关闭提示/大厅 | 原房间删除。 |
| 联机房间 | 服务连接中断 | 本端大厅 | 本局不保存，不能自动续局。 |
| 联机房间/大厅 | 切回闯关 | 闯关对应阶段覆盖层 | 已入房者先离开房间；仅原阶段为战斗时显示继续，闯关存档不变。 |

## 附录 B. 操作权限矩阵

当前权限只由本端模式与房内身份决定，不依赖账户；同一浏览器用户可依次成为闯关玩家、房主或加入者。

| 角色 | 逻辑页面 | 是否可见 | 可操作项与限制 |
|---|---|---|---|
| 闯关玩家 | 闯关舞台与路线 | 是 | 战斗中移动、拳、踢、跳、闪；符合资格、有充能且场上有活敌人时光波；点路线只读提示、不得跳关。 |
| 闯关玩家 | 闯关状态覆盖层 | 是 | 开始/继续、失败回档重试、过关下一关；全部通关后确认/取消重开。 |
| 闯关玩家 | 联机大厅 | 切换后可见 | 未入房时可选择主题建房，或输入房码加入；成功后成为 P1/P2。 |
| 房主 P1 | 联机房间面板 | 是 | 建房前选择主题；入房后复制房码、退出；结束后申请再战；不能在房内另建/另加房、不能入房后改主题。 |
| 房主 P1 | 联机战斗/覆盖层 | 是 | 本人移动、拳、踢、跳、闪；不能操作 P2，也不能用光波；对方离开后可用原码邀请新对手。 |
| 加入者 P2 | 联机房间面板 | 是 | 入房前输入六位码；入房后复制房码、退出；结束后申请再战；不能改房主主题或在房内另建房。 |
| 加入者 P2 | 联机战斗/覆盖层 | 是 | 只操作本人的移动、拳、踢、跳、闪；不能操作 P1 或使用光波；房主离开后只能返回大厅重新建/加房。 |
| P1/P2 | 闯关舞台 | 切换后可见 | 切回前离开联机房间，随后只按本浏览器的闯关记录操作。 |
| 任一角色 | 页头音效 | 是 | 切换本端合成音效开/关，不修改对手设置或闯关进度。 |

## 附录 C. 枚举、状态与口径

| 对象 | 字段/状态 | 枚举值或流转 |
|---|---|---|
| 顶部模式 | 当前入口 | `campaign` 闯关；`duel` 联机。默认闯关，互相切换不更改关卡进度。 |
| 闯关阶段 | 当前阶段 | `idle` 内部初始 → `playing` 战斗 → `failed` / `cleared` / `completed`；失败重试、过关下一关和确认重开均回到 `playing`。 |
| 闯关记录 | 完成标记 | `false` 未通关全部 56 关；`true` 第 56 关已完成。失败次数为非负整数，已通关集合为关卡编号。 |
| 路线节点 | 显示状态 | 当前、已通关、锁定；存档与 Boss 为叠加标记而非可选关权限。 |
| 主题 | 主题 ID/名称 | `forest` 森林、`city` 城市、`ocean` 海洋、`land` 陆地；建房默认城市。 |
| 敌种 | 关卡敌人 | 斗士、疾行者、盾卫、重拳手、Boss。Boss 的具体名称随关卡配置。 |
| 联机角色 | 房间身份 | `p1` 房主、`p2` 加入者；同一房间恰好至多两人。 |
| 房间阶段 | 生命周期 | `idle` 未入房 → `waiting` 房主等待 → `countdown` 双方倒数 → `playing` 对战 → `finished` 结算；两人申请重赛后回 `countdown`。P2 离开使房主回 `waiting`；P1 离开/连接断开使客人回 `idle`。等待房过期的客户端状态例外见 G-01。 |
| 对战结算 | 原因/结果 | `ko` 任一生命归零；`timeout` 时间用尽。胜者 P1/P2 按剩余生命比较，相等为无胜者/平局。 |
| 房间反馈 | 常见错误 | 非六位数字码、房间不存在/已结束、房间已满、已在其他房间、不能在当前阶段重赛、连接失败等；错误只提示，不暗中变更另一房间。 |
| 光波 | 可用状态 | 关卡敌人总数 >3 才适用；战斗阶段、玩家存活、当前波有活敌人且次数 >0 才可发动。UI 分为不适用（隐藏）、充能中（不可用）、可发动（显示次数）。 |
| 坠物 | 类型 | 森林松果、城市碎片、海洋冰雹、陆地小石；只在偶数闯关关卡。 |
